Treasury Management Portal — Design System

Remit4Me for EBIXCASH World Money Ltd. Palette and typeface extracted from the v1 deck (28 slides), not invented. Every component below is used by at least one of the 53 screens. Approve or adjust this before screens are drawn — everything inherits from here.

Design noteThe deck uses #A43E3E exactly twice in 28 slides — on B-01's "due before cut-off" count. That restraint is deliberate and is preserved: status is a label first, colour only reinforces it. One colour was added, #8A6832, because six statuses cannot be encoded with one signal colour. It was darkened from the tonal sibling of the red so it clears AA at 4.9:1. --muted was darkened from #657C81 to #596D71 for the same reason: it is used for 11px column headers, which WCAG counts as small text and holds to 4.5:1.

font-variant-numeric: tabular-nums is set globally on every figure class.

Arial ships tabular figures by default, so this looks correct today. It stops being true the moment anyone swaps the typeface — which is likely, since the engineering stack is undecided. The declaration is insurance, not decoration.

Scan the INR column: decimal points align, so an order-of-magnitude error is visible as a ragged edge rather than something you have to read for.

Rates 4 decimals (84.2500) · FCY 2 decimals · INR in Indian grouping (4,20,00,000) and crore when consolidated · all times IST, zone shown · currency code always adjacent to the amount.

11 · Rules this system enforces

RuleHow the design carries it
Booked = linked + remaining + cancelledStat strip on B-04 and the blotter footer make the identity visible; the three columns always appear together.
Txn matching ≠ bank coverageTwo separate status columns that are never merged. A row can read Awaiting txn and Covered at once.
Never total mixed currenciesFooters total one currency and label it. INR equivalents always carry a valuation basis and timestamp.
Maker-checker is visibleBefore/after column pair, maker name and time, disabled approve with the reason stated.
Suggestions never auto-commitMatch reason is shown per row; confirm is always a separate human action.
Stale data stays visibleStale badge, source timestamp, and explicit exclusion from subtotals.
Status never by colour aloneEvery pill carries a word. Greyscale-safe.

12 · Interaction layer

Every actionable control in the prototype resolves to a real dialog — there are no dead buttons. The engine is tmp.js, ~150 lines of vanilla JS over the native <dialog> element, which supplies focus trapping, Esc-to-close and the backdrop without a library.

PatternContract for the dev team
Open a dialogdata-dlg="dlg-id" on any button. The dialog markup ships on the same page.
Commit an actiondata-confirm="toast text". Validates, closes, then raises a toast.
Mandatory reasondata-required on the textarea. Commit is blocked and an inline error shows until it is filled.
Blocked actionNative disabled plus the reason in view. Never hide why. A checker's own entry is the canonical case.
Live recalculationdata-alloc scope with data-amt rows; residual, remainder and over-allocation recompute on every tick.
Read-only role.ro on the app root removes action affordances entirely rather than disabling them.

Full catalogue of every dialog: UX-04. Environment, freshness and role states: UX-05.

Rules the dialogs enforce No silent destruction — a destructive dialog names the record count and the exact effect before you commit. Reason mandatory on reject, cancel and adjust, and it travels back to the maker. Suggestions never auto-commit; confirming is always a human action.
