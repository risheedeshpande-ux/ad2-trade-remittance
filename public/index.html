Run the demo

Open the demo and click Demo guide. It walks one new business through 17 steps — registration, maker review, checker approval, an import bill, a DIR payment verified, authorised and released, then an export receipt disposed and a FIRC issued. Each step signs in as the right person with one click, so you can watch the work move from role to role.

Then open the Test data lab from the sidebar. It creates fresh businesses, bills, receipts and requests parked at each stage, and lists ten more journeys to try — partial and advance disposals, EEFC credit, FIRC knock-off, LC settlement, a High-risk payment, queries and the assisted journey — so nothing runs out.

Signing in

Worth showing

WhereWhat to do
Outward → New request Switch between AIR, DIR and OTT: the purpose codes and documents follow the business team's workbook. Under OTT, type a large amount and Form 146 becomes required; pick a goods code and the transport document does too.
Any approval Try to authorise as the maker who verified — the button is not there, and the API refuses it even if called directly.
Release a payment Operations sees the account balance, releases, and gets a UTR, a SWIFT MT103 and a printable payment advice. The linked bill settles.
Two browsers Open the demo in two windows as different roles. Act in one; the other's queue updates within seconds.
Administration Stop a purpose code being offered, or make a document optional, and the next request reflects it.

Resetting

The demo keeps one shared state on the server, so everyone using the link sees the same data. Reset demo data in the yellow bar restores the starting data for everyone (it asks for the passcode where one is set).

Scope

Enforced for real: authentication, roles, four-eyes, the purpose and document policy, rates, balances, bill reservation and the audit trail. Simulated: the FX feed, SWIFT, PennyDrop, sanctions screening, SFTP, SAP and document AI. Before production: the FX quotation formula from treasury, transaction limits from risk, the SFTP/SAP contracts, document storage and retention, and a relational database in place of the demo store.
